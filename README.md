# ShopBlock 商店模块 README

> 定位：酒馆助手（TavernHelper）第四联动模块「商店」，与 mms 状态栏（MiniMapStatus）、副导演（AssistantDirector）、战斗前端（RpgCombat）联动。
> 本文描述**最终交互逻辑**（待用户确认）与 **MVP 分步计划**。数据格式契约见 `SPEC.md`。

---

## 一、总体形态

- 单 HTML 楼层 iframe 组件（RpgCombat 同款形态）：正则把正文中的 `<Shop_block>...</Shop_block>` 替换为商店界面。
- 店主立绘 10 类枚举，资源挂本地服务器 `D:\Project\my_assets\shop_resources\`，根 URL 在设置弹窗可配置。
- 双 LLM 分工：
  - **正文 AI**（主 LLM）：生成 `<Shop_block>` 原始数据（店名/店主/立绘/性格/在场成员/商品/私藏/介绍文案），叙述购买与搬运过程。
  - **独立 LLM**（前端直连 OpenAI 兼容接口）：店主对话、队友插话、好感增减、add/regroup 功能命令。
- 数值铁律：现金、物品、好感度变动全部由**后台程序**执行，LLM 只产出叙事文字和意向命令，程序校验后落地。

## 二、完整交互流程（最终逻辑，待确认）

### 1. 进店（触发与初始化）

1. 正文 AI 在剧情推进到进店时输出 `<Shop_block>`（提示词注入 10 类立绘菜单与人设锚点，先选立绘再写店主人设；已开过的店会注入 `$shops` 旧数据供续写保持一致）。
2. 前端解析块 → 以店名合并进聊天变量 `$shops`（同名商品覆盖、新商品追加、旧类目保留，好感度延续）。
3. 界面渲染：店主立绘（枚举→本地服务器 URL）、店名、分类 Tab（自动生成）。
4. 读取 MMS：回溯 ≤50 楼取最新 `stat_data` → 在场团队（与块的`在场成员`取交集）、团队现金、成员头像。
5. **自动调用独立 LLM（进店反应）**：上下文 = 最近 2 层正文 + 报纸（最近 `<Newday>`）+ 风声（`$ad_world.winds`）+ 当前商品清单 + 在场名单。店主先对玩家作出反应，在场队友可插话（气泡/对话框逐条展示）。

### 2. 浏览商品

- 商品按类目分 Tab 陈列；`数量>1` 的商品走拉条复数购买，单件商品点击直接入车。
- **悬浮 / 点击商品气泡**：显示正文 AI 生成的`介绍`文案（店主口吻），不调用 LLM。
- **独家私藏**：好感度 <100 时整类隐藏，不可见不可买；=100 时解锁显示与购买。

### 3. 自由对话（打探、问货）

1. 玩家在底栏选择发言角色（玩家操控角色，头像来自 MMS），输入文字发送。
2. 独立 LLM 返回 `dialogue`（店主 + 队友，**白名单硬规则**：只能代言店主和在场固定角色中除当前发言者外的人，玩家台词永远来自输入框；越权 speaker 解析端直接丢弃）、`affection`（好感增减，程序钳制 0~100）、可选 `commands`。
3. **add 命令（反许愿机四重限制）**：玩家问"有没有 X"而店里没有时，LLM 在自然对话末尾附带 add 命令把 X 加进货架，玩家当场可买。限制：
   - **渠道合理性（LLM 侧）**：只有常规补给类商品（食品、日用、常规药品、通用弹药等普货）可 add；违禁品、神话物品、超时代科技、大宗军火必须拒绝，店主以人设口吻回一句"弄不到"的说辞——提示词明确"你不是许愿机"。
   - **类型锚点校验（程序侧）**：add 商品的类目必须落在该店立绘类型的货品锚点范围内（见 SPEC 枚举表），越界命令直接丢弃（对话照常显示，货不上架）。
   - **频率限制（程序侧）**：每次进店会话 add 落地 ≤1 条，超出的静默丢弃。
   - **价格约束（LLM 侧）**：add 商品价格参照店内同类商品定价，不得免费或象征性收费；讲价投骰对 add 商品同样适用。

### 4. 讲价（砍价按钮 + 投骰 + LLM 店主回应）

1. 玩家点击输入框右侧「砍价」按钮进入砍价模式 → 单击目标商品 → 弹出砍价拉条（5~30%）→ 确定。
2. 程序把斜体包裹的 `*{{角色名}}尝试砍价，砍价后价格为XX。*` 自动填入对话框；玩家可继续以该角色身份补充台词（讨好的、强硬的都行），也可直接发送。
3. 发送时后台投骰（不经 LLM）：`1d100 + 好感度×0.5 ≥ 40 + 幅度×2`。
4. 按投骰结果给独立 LLM **不同分支的提示词**，店主以人设口吻返回结果：成功（爽快或勉强答应，按人设）、失败（拒绝）、二次失败（明显不耐烦，态度按人设演绎）。LLM 不可用或解析失败时才回退内置文案库。
5. 成功后该商品按折后价入车；**同时程序自动把折后价写回商品柜**——该商品以砍价者名义锁定折后价（商品卡显示划线原价 + 折后价 + 砍价者角标，本店会话内其他人再来买也是折后价；好感度 100 解锁私藏后同理适用），限砍计数与锁定价随商品生效，进店会话结束（刷新/重进店重新解析块）后重置为块内原价；失败维持原价，玩家可放弃或原价购买。
6. **同一商品最多砍两次**：第二次幅度更大 → 免投骰直接拒绝（LLM 收到"玩家得寸进尺，直接拒绝"提示，附好感惩罚）；幅度更小才重新投掷。
7. 砍价场景的好感变动 = 程序贪婪惩罚（第 8 节）+ LLM 对话判定（玩家嘴甜可小幅挽回，出言不逊雪上加霜），两项叠加。

### 5. 购买结算（数值直连 MMS，不走 LLM）

1. 购物车累积条目（单件直入 / 拉条复数 / 砍价成功按折后价）。
2. **结算框多选归属**：打开结算框，商品为多选模式；勾选若干商品后，点击底栏在场团队角色头像或载具图标 → 该批商品直接放入对应角色/载具的物品栏；剩余商品可继续勾选分配给他人。**点击「确认结算」前全部可撤销**（从归属栏移除即回到待选池）。
3. 确认结算（带**二次扣除锁**，RpgCombat 战斗硬锁同款，防止状态栏更新 LLM 读到购买叙事后重复扣减）：
   - 幂等台账 `$shop_sync`（`{lastId, appliedFloor, ts}`）比对本次结算 id，已应用则跳过——防重试/事件重放；
   - 校验团队现金（MMS `stat_data` 现金字段）充足；
   - 程序直接写最新 AI 楼 `stat_data`：现金扣减、个人物品入 `角色列表[角色].物品`、载具物品入 `载具` 模块清单；`replaceVariables` + `eventEmit('mms:status-updated')` 通知状态栏即时刷新；
   - 写真值载荷 `$shop_deal_result`（幂等 id + `lock` 硬锁清单：锁现金 + 锁各角色/载具新增物品条目）供对账；MMS 更新合并层据此**丢弃**锁定项的更新 LLM 数值命令（硬锁仅在购买叙事仍在更新 LLM 上下文窗口内时有效，过期自动失效）；
   - 按折后实付金额结算购物好感（第 8 节）。
4. **独立 LLM（购买回应）**：输入购物明细 + 归属方案 + 讲价结果 → 店主回应、队友插话。
5. **商店记录注入**：结算完成后程序组装本次进店记录（见第 9 节），填入酒馆输入框，玩家确认/修改后发送，正文 AI 据此续写购买与搬运过程。

### 6. 离店与回访

- 关闭界面即离店，`$shops` 数据（含好感度）持久保留。
- 二次进店：正文 AI 再输出同店名块 → 合并商品 → 独立 LLM 进店反应（好感度延续影响态度）。
- **重排商品按钮**：二次进店可能产生"枪械/武器"类同义重复类目，点击按钮发起独立 LLM regroup 调用，返回合并后的类目映射，程序按名字搬家（未出现的商品原地不动，私藏不参与），弹确认框可撤销。

### 7. 设置

- 设置弹窗：独立 LLM 的 apiBase/apiKey/model/systemPrompt + **立绘服务器根 URL**，localStorage 持久化。

### 8. 好感度算法（贯穿全程，程序结算，钳制 0~100）

三个来源叠加，互不替代：

| 来源 | 触发时机 | 数值 | 判定方 |
|---|---|---|---|
| 对话好感 | 每次含玩家台词的场景（自由对话 / 砍价 / 购买回应） | `affection` 字段 -5~+5，按玩家言辞（礼貌 / 冒犯 / 投机 / 共情 / 掏钱爽快程度）判定本次对话让店主产生的态度变化 | 独立 LLM |
| 购物好感 | 每次结算成功（按折后实付金额） | 每满 5 美元 +1，不设单次上限（1920 年代 5 美元已是小巨款，大主顾理应换来店主的殷勤） | 程序 |
| 砍价惩罚 | 砍价失败 / 二次贪婪 | 首次失败 `-⌈幅度÷10⌉`（砍 10% → -1，砍 30% → -3）；二次失败翻倍；二次更大幅度被直接拒绝 -2；砍价成功不扣（凭本事谈成） | 程序 |

- 进店反应（无玩家台词）不产生好感变动。
- 好感度影响三处：100 解锁独家私藏；拼进独立 LLM 的 system prompt 影响店主态度；投骰公式加值影响讲价成功率。

### 9. 商店记录模块（RpgCombat 战报同款思路，注入聊天框续写）

结算完成后，程序把本次进店会话组装成记录文本，**填入酒馆输入框**，玩家检查/修改后发送，正文 AI 据此续写购买与搬运过程。会话数据（对话流水）在进店期间内存收集，不持久化。

```html
<Shop_Record>
商店: 出征杂货铺 (店主: 老萨姆 · 立绘: 占卜商妇 · 讲价结果: 10%成功)
本次对话:
  埃利奥特: "老板，上次那批杀虫粉还有吗？"
  老萨姆: "哟，稀客。这周刚到的货，就是涨了点价。"
  弗兰克: "涨价？看在老主顾份上便宜点。"
  *埃利奥特尝试砍价，砍价后价格为XX。*
  老萨姆: "行吧，看你是熟面孔。"
购买清单:
  - 基廷氏杀虫粉 ×6 = $15.00（折后价）→ 归属: 埃利奥特
  - 石炭酸皂 ×4 = $3.20（原价）→ 归属: 载具（防弹轿车）
实付总额: $18.20，团队现金余额: $4744.70
</Shop_Record>
```

- 内容四要素：玩家发送的全部消息（含砍价斜体宣言）、所有 LLM 返回的对话（店主+队友）、最终购买清单（数量/价格/折后）、物品归属（角色 or 载具）。
- 玩家发送前可删改记录文本（不想让正文 AI 看到的插话可以抹掉）。
- `<Shop_Record>` 加入上下文剥离列表：商店独立 LLM 组装上下文时与 `<Shop_block>` 一并剥掉，避免记录复读。

## 三、联动契约速览

| 通道 | 内容 |
|---|---|
| 正文 AI → 商店 | `<Shop_block>` YAML（店名/店主/立绘/性格/在场成员/分类商品/独家私藏） |
| 商店 → 正文 AI | `<Shop_Record>` 进店记录（结算后填入酒馆输入框，正文续写购买/搬运过程） |
| 商店 → 聊天变量 | `$shops`（以店名为键，中文键直存，含好感度） |
| 商店 → MMS | 直写 `stat_data`（现金/物品）+ 事件 `mms:status-updated` + `$shop_deal_result`（含 lock 硬锁清单）+ `$shop_sync` 幂等台账（二次扣除锁） |
| MMS → 商店 | `stat_data`（在场团队/现金/头像）、`$mms_roster`（固定角色）、`AVATAR_MAP`（头像） |
| 副导演 → 商店 | `$ad_world.winds`（风声）、正文 `<Newday>`（报纸），作独立 LLM 上下文。**弱耦合可选源**：副导演未启用时自动降级为空，商店完全可用 |

## 四、最小 MVP 分步计划（每步可独立验证）

原则：每步完成后都有可观察的验证点（node --check / IAB mock / harness 断言），通过才进下一步。MVP 范围 = 上文流程 1/2/5 的核心闭环 + 讲价；对话、add/regroup、私藏、报纸风声上下文为增量阶段。

### M1 解析与渲染（纯前端，无酒馆依赖）
- 内容：`<Shop_block>` 解析器（lastIndexOf + js-yaml 容错）、把现有写死 `shopInventory` 替换为"解析结果驱动渲染"（分类 Tab、拉条、气泡介绍文案）。
- 验证：IAB 打开 index.html，粘贴一段含极端格式（缺字段/多余空格/引号内冒号）的 `<Shop_block>` 文本到导入框，界面正确渲染且控制台零报错；解析失败时显示手动粘贴回退框（RpgCombat 同款）。

### M2 立绘枚举与资源路径
- 内容：10 类枚举表、设置弹窗增加立绘服务器根 URL 配置（localStorage）、枚举→URL 映射 + onerror 回退占卜商妇。
- 验证：IAB 中把根 URL 指向本地静态服务器（或 file 路径），切换/填错枚举时正确回退；10 张图逐一加载成功。

### M3 `$shops` 持久化与合并（mock 酒馆 API）
- 内容：`getVariables/insertOrAssignVariables type:'chat'` 读写、同店名合并规则、好感度字段、删除用 replaceVariables。
- 验证：harness（mock tavern API）注入两次同店名不同商品的块，断言：商品合并正确、好感度保留、`$shops` 键结构符合 SPEC。

### M4 独立 LLM 通道（进店反应场景）
- 内容：fetch 封装 + extractJson 容错解析、三段式上下文组装（先只接"最近 2 层正文"，报纸/风声后补）、dialogue 气泡渲染（店主 + 队友）、代言白名单校验、affection 落地、无 Key/失败回退内置文案库。
- 验证：harness mock 一个返回固定 JSON 的假 LLM 端点，断言：气泡按序展示、白名单外 speaker 被丢弃、好感度累加钳制；断网/返垃圾文本时回退文案出现。

### M5 讲价与好感度
- 内容：砍价按钮/单击选品/拉条 UI、斜体宣言 `*{{角色名}}尝试砍价，砍价后价格为XX。*` 自动填入对话框、投骰判定、同商品两次限制与二次幅度校验（更大免投骰直接拒绝）、LLM 四分支提示词（成功/失败/二次失败不耐烦/二次贪婪拒绝）+ 内置文案回退、好感度三来源算法（对话/购物/砍价惩罚）落地。
- 验证：harness monkey-patch Math.random 断言边界值（刚好过线/差 1 点）成败分支；二次大幅被拒时免投骰且好感 -2；好感三来源叠加与 0~100 钳制正确；斜体宣言文本格式断言。

### M6 MMS 直连桥（结算闭环，MVP 核心里程碑）
- 内容：读 `stat_data`（回溯 ≤50 楼 + mesId 校验）取在场团队/现金/头像（AVATAR_MAP 三路取值）；结算框多选归属 UI（勾选商品→点角色头像/载具放入，确认前可撤销）；结算写现金/物品 + `eventEmit('mms:status-updated')` + `$shop_deal_result`（含 lock 硬锁清单）+ `$shop_sync` 幂等台账；购物好感每满 $5 +1 不设上限；`<Shop_Record>` 记录组装并填入酒馆输入框。
- 验证：harness 造 mock stat_data（含现金模块、角色列表、载具模块），完成一次多商品分归属购买，断言：现金扣对、物品落在选定角色/载具、撤销后物品回到待选池、载荷结构正确、现金不足时阻断、好感按实付金额累加、记录文本含四要素且格式正确；**重复触发结算（模拟重试/事件重放）时 `$shop_sync.lastId` 比对生效、stat_data 零二次写入**；真机：与真实 mms 状态栏同场联调，状态栏数值即时刷新。

### M7 独立 LLM 全场景 + 功能命令（增量）
- 内容：自由对话、购买回应两场景接入；add 命令（四重限制：渠道合理性提示词、锚点类目校验、每次进店 ≤1 条、价格参照同类；禁私藏）；重排按钮 regroup 调用 + 确认框。
- 验证：harness 假端点断言各场景触发器正确组装；add 重复名不重复添加；锚点越界类目被丢弃；同会话第二条 add 被频率限制拦下；regroup 未列出商品原地不动。

### M8 私藏与收尾（增量）
- 内容：好感度 100 解锁私藏 Tab、报纸/风声上下文接入、购买回应后的正文叙述依赖注入词条。
- 验证：harness 把好感度设 100 断言私藏出现；真机完整流程走一遍（进店→对话→讲价→买→出店→再进店）。

### M9 打包交付
- 内容：build 脚本生成正则 JSON 产物（对齐 RpgCombat/MMS 构建链）、组件围栏断言（`` ` `` 序列数 == 2）、README/SPEC/LOG 更新。
- 验证：`node --check` 通过；正则 JSON 导入酒馆后真机冒烟。

### 用户真机测试事项

**环境准备：**
- 启动 `D:\Project\my_assets\启动my_assets服务器.bat`（8766 端口），否则店主立绘/头像回退。
- 酒馆内确认 MMS 状态栏正则已启用（商店读 stat_data 现金/角色/载具）；副导演/NewDay 可选，未启用只是店主少了谈资（降级为空）。
- 商店设置弹窗：独立 LLM 的 apiBase/apiKey/model；立绘/头像根 URL 留空即默认 8766。

**核心流程走查：**
1. 让正文 AI 输出含 `<Shop_block>` 的进店剧情 → 楼层渲染商店、店主立绘正确（人设与立绘类型不冲突）。
2. 悬浮/点击商品 → 店主气泡显示正文 AI 写的介绍。
3. 对话：选角色发言 → 店主+队友回应；问店里没有的常规补给品 → add 上架（违禁品/神话物品应被拒）；连问第二次 → 频率限制（整次进店只落地 1 件）。
4. 砍价：砍价按钮 → 点商品 → 拉条 → 斜体宣言发送 → 投骰结果（成功折后价回写货架带角标；同商品二次更大幅度直接拒；第三次拒谈）。
5. 购买：多选商品 → 点角色头像/载具分配 → 确认结算 → MMS 状态栏现金/物品**即时刷新**（关键联调点）。
6. 结算后输入框自动填入 `<Shop_Record>` → 检查/删改后发送 → 正文续写购买搬运过程。
7. 重复发送结算（如刷新后重试）→ `$shop_sync` 幂等，现金不应二次扣除。
8. 好感：连续购买/嘴甜对话涨好感；到 100 时私藏 Tab 解锁（店主开柜演出）。
9. 出店再进店 → 商品合并、好感延续；类目重复时点「重排商品」→ LLM 归类 → 可撤销。

**已知边界：**
- 独立 LLM 不可用时：对话/进店反应回退内置文案，砍价回退内置分支文案，商店仍可浏览结算。
- MMS 未运行时：现金显示回退本地 demo $280，结算不写 stat_data（仅账本记录）。
- 窄屏（≤640px，手机竖屏 / 酒馆侧栏挤压）：自动切换窄屏布局——顶栏与分类头换行、货柜 5 列→3 列（柜内滚动保持）、立绘展台压矮、输入栏动作按钮图标化、弹窗 92vw/86vh 兜底（`integration-test/narrow-harness.html` 15 断言锁行为）。
